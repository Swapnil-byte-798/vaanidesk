# Portfolio rules

Use Python and SQL. Do not author JavaScript, TypeScript, HTML/CSS, React or another custom frontend. Prefer FastAPI generated documentation and Python CLI commands. Preserve one independently installable project per folder.

Do not store credentials in source, test reports or Git. Live commands must fail clearly when credentials or external models are unavailable. Unit fixtures are not live provider evidence. Store test scope and measured results honestly.

Use meaningful domain tests, transaction and security tests, provider-contract tests, and runnable packaged examples. Each project needs requirements, architecture, a runbook and study notes.
